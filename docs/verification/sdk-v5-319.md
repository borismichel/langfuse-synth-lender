# SDK v5 Lending release verification

Lending v0.7.0's first fresh Cloud admission failed only `run_filing_evidence`:
0 of 216 linked observations passed. The experiment items, scores, prompts, costs,
golden traces, review queue, and managed evaluator configuration passed. No data
was reimported and no model call was repeated during diagnosis.

## Cause and retained contract

The captured Cloud observations response presents the question as four dotted
metadata fields: `analyst_question.case_id`, `.borrower`, `.question`, and
`.excerpts`. The verifier expected one nested `analyst_question` object. The full
input already decoded to the original dataset input, and the linked IDs matched.
All four metadata fields equalled the hosted dataset question, including 1,131
characters of filing excerpts (1,325 characters for the full question). Explicit
metadata expansion returned the same complete values.

The v0.7.1 verifier reconstructs only this known kit-owned namespace when the
nested object is absent. It still compares the full observation input and every
structured question field. It does not fall back to a sibling observation or
accept scores as evidence. Nested metadata remains supported. The shared core,
SDK experiment writes, and managed evaluator mappings are unchanged: judges read
the full linked observation input and output, with inherited rule mappings.

## Regression and validation

An exact captured-response replay through public `run_verify` failed in 0.19s
with 0/1 filing observations, then passed in 0.17s after the correction. Changing
only the metadata representation in a diagnostic replay also passed, isolating
the cause from item identity and input decoding.

The repository regression first failed only `run_filing_evidence` for dotted
metadata. Both supported shapes now pass; changed input, missing metadata,
changed unit note, section ID, printed sign, and missing linked observation still
fail for both shapes. The 14-day and 30-day real-SDK/export rehearsal fixtures now
project the observed dotted metadata and raw JSON input/output wire shape.

  golden checks, full 216-item/1,080-score evidence checks, and setup readback.

  Companion shape advisories remain (`/` health path and missing target factory).

The immutable v0.7.0 release is preserved. The signed v0.7.1 candidate subsequently
passed all six admission gates on a fresh Cloud target, including complete filing

## v0.7.2 live persistence and escalation event

The deployed v0.7.1 Companion completed its SDK certification experiment, then
failed while saving the summary to `.synth_spool/.synth_state.json`. Depot mounts
that imported seed-state volume read-only. The actual Companion root filesystem
and existing `.workbench` store are writable. Workbench execution used the same
seed-state write and would fail at the same boundary.

Live certification and workbench now save independent, atomically replaced run
summaries under `workbench.results_dir/live-runs`. Dossier and memo readers merge
those summaries with seed anchors in memory. Seed verification continues to read
only the unchanged seed state. Summaries are scoped by a fingerprint of the seed
anchors to prevent records from another project or seed appearing in the dossier.
The local index has the same lifetime as the Companion's existing workbench store;
Langfuse remains the durable experiment record.

A second live readback found that the `escalated_to_human` event had no output.
SDK events end at creation, so its later update was ignored. The caller now passes
the existing simulated handoff output (`queued: true`) at creation. Event type,
name, input, metadata and parent remain unchanged; no external queue is introduced.

- Real-SDK certification regression: read-only seed anchors first raised
  `PermissionError`; the corrected path completes and appears in memo/dossier.
- Real-SDK workbench regression: the same boundary first produced an error run;
  the corrected path completes and appears alongside the certification and seed.
- Seed bytes remain identical, direct seed reads exclude live summaries, and a
  different project does not inherit those summaries.
- Real OTLP export first omitted event output and warned that events cannot be
  updated; the corrected event retains its output and parent without warnings.
- Full suite: **265 passed**, including unchanged Spool/UI goldens and the full
  216-item/1,080-score evidence checks. Contract conformance retains only the two
  existing Companion shape advisories. `git diff --check` is clean.

Core remains v5.0.0 and Python SDK remains exactly 5.0.1. Signed v0.7.2 publication,
fresh admission and live rehearsal are pending release gates. These local tests
use controlled service/model transports and do not claim a passing live model run.
